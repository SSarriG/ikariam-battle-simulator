⚠️ CAMBIOS CRÍTICOS - Versión 3.0
Esta versión incorpora hallazgos del estudio académico de AT Barbarossa y Xanto sobre mecánicas avanzadas del sistema de combate de Ikariam. Los cambios fundamentales son:
1. Attacking Matrix (Am Theory)
* El sistema NO distribuye ataques "unidad por unidad"
* Cada línea forma una matriz n×m donde las filas atacan slots específicos
* La distribución sigue un patrón matemático preciso basado en módulo
2. Slot Renumbering
* Los slots NO se atacan en orden físico [1,2,3,4,5,6,7]
* Cada tipo de línea tiene un orden de renumeración específico
* Primera/Segunda Línea: [6, 4, 2, 1, 3, 5, 7] (slot 1 recibe más daño)
3. Damage Redistribution (3 tipos)
* Reserve-Redistribution (RR): Entre rondas, daño se redistribuye entre todas las unidades vivas
* Slot-Redistribution (SR): Después que una línea dispara, daño se redistribuye dentro de slots
* Immediate-Redistribution (IR): Durante ataque, daño se redistribuye inmediatamente (Portaglobos/Espolones)
4. Kill Types (6 tipos diferentes)
* 1-kill, D-kill, P-kill, I-kill, IR-kill, M-kill
* El tipo de kill depende de la composición de la matriz de ataque
* Columnas pares vs impares tienen comportamientos diferentes
5. Accuracy NO es siempre 100%
* Algunas unidades (ej: Spearmen 70%) tienen precisión variable
* Solo el % de unidades dispara efectivamente
6. Mejoras Individuales + Hefesto Global
* Mejoras: Aplicadas INDIVIDUALMENTE a cada unidad (puedes tener grupos con diferentes mejoras)
* Hefesto: Aplicado GLOBALMENTE a todas las unidades según nivel (0-5)
7. Portaglobos/Espolones - Immediate Redistribution
* NO es "sistema de turnos" ni "cobertura mutua"
* Es Immediate Redistribution (IR) activada por umbral de unidades
* El daño se DIVIDE entre todas las unidades del grupo

1. Investigación del Sistema de Batallas
1.1 Mecánicas Fundamentales de Ikariam
1.1.1 Estructura del Campo de Batalla
El sistema de batallas de Ikariam utiliza una estructura de campo de batalla por slots que varía según el nivel de la ciudad (terrestre) o puerto (marítimo).
Tipos de Líneas de Batalla:
1. Primera Línea (primera-linea): Unidades de combate cuerpo a cuerpo pesadas
2. Luchadores a Distancia (luchadores-distancia): Unidades de ataque a distancia
3. Flancos: Unidades ligeras de infantería
4. Artillería: Unidades de asedio y bombardeo pesado
5. Bombarderos: Unidades aéreas ofensivas
6. Anti-aérea (anti-aerea): Unidades de defensa contra bombarderos
Análisis de campos.json:
Batallas Terrestres:
* Nivel 1-4 ciudad: 3 slots primera línea, 3 luchadores distancia, 0 flancos, 1 artillería (30 unidades/slot)
* Nivel 5-9 ciudad: 5+5+2+2 slots (30 unidades/slot)
* Nivel 10-16 ciudad: 7+7+4+3 slots (30 unidades/slot)
* Nivel 17-24 ciudad: 7+7+6+4 slots (40/30 unidades/slot)
* Nivel 25+ ciudad: 7+7+6+5 slots (50/40/30 unidades/slot)
Batallas Marítimas:
* Nivel 0-7 puerto: 3+3+0+1 slots (15 unidades/slot)
* Nivel 8-14 puerto: 5+5+2+2 slots (15 unidades/slot)
* Nivel 15-21 puerto: 7+7+4+3 slots (15 unidades/slot)
* Nivel 22-28 puerto: 7+7+6+4 slots (20/15 unidades/slot)
* Nivel 29+ puerto: 7+7+6+5 slots (25/20/15 unidades/slot)
Bombarderos y Anti-aérea:
* Terrestres: 1-2 slots con capacidad 10-30 unidades
* Marítimas: 1-2 slots con capacidad 10-15 unidades
1.1.2 Sistema de Daño y Armadura
Fórmula Base de Daño:
Daño Efectivo = MAX(0, Daño Atacante - Armadura Defensor)
Componentes del Daño:
* Daño Base: Definido en unidades.json para cada tipo de unidad
* Armadura: Reduce el daño recibido punto por punto
* Precisión (Accuracy): NO siempre 100% - algunas unidades tienen precisión variable
* Puntos de Golpe (HP): Vida total de la unidad
Sistema de Mejoras INDIVIDUALES:
⚠️ IMPORTANTE: Las mejoras se aplican INDIVIDUALMENTE a cada unidad, NO globalmente por tipo.
Cada unidad puede tener nivel de mejora 0, 1, 2, o 3:
* Nivel 0: Stats base sin mejoras
* Nivel 1: daño-mejora1, armadura-mejora1
* Nivel 2: daño-mejora2, armadura-mejora2
* Nivel 3: daño-mejora3, armadura-mejora3
Ejemplo de Composición Mixta:
Atacante tiene:
* 100 espadachines mejora 0 (daño 10, armadura 0)
* 50 espadachines mejora 2 (daño 13, armadura 4)
* 30 espadachines mejora 3 (daño 16, armadura 7)
Total: 180 espadachines con 3 niveles de mejora diferentes
Los valores de mejora están definidos en unidades.json para cada tipo de unidad.

⚠️ IMPORTANTE: Hefesto se aplica GLOBALMENTE a todas las unidades del bando, independiente de sus mejoras individuales.

1.2 Distribución de Unidades en Slots
1.2.1 Algoritmo de Llenado de Slots
Análisis de lineas.json:
Cada línea tiene una prioridad de posición específica que define el orden en que las unidades llenan los slots disponibles.
Ejemplo Primera Línea Terrestre:
1. Hoplita (tamaño 1)
2. Gigante a Vapor (tamaño 3)
3. Espadachín (tamaño 1)
4. Lancero (tamaño 1)
5. Fusilero (tamaño 4)
6. Arquero (tamaño 1)
7. Hondero (tamaño 1)
Algoritmo de Distribución:
Para cada slot en la línea:
capacidad_slot = tamaño-por-hueco
unidades_restantes = capacidad_slot
Para cada grupo_unidad en orden de prioridad:
cantidad_disponible = grupos[tipo_unidad][nivel_mejora]
tamaño_unidad = unidades.json[tipo_unidad].tamaño
unidades_que_caben = MIN(cantidad_disponible, unidades_restantes / tamaño_unidad)

asignar unidades_que_caben al slot
unidades_restantes -= unidades_que_caben × tamaño_unidad

Si unidades_restantes == 0: pasar al siguiente slot

Comportamiento Clave:
* Las unidades se distribuyen por prioridad dentro de la línea
* Grupos con diferentes mejoras se tratan como grupos separados
* Cada slot tiene una capacidad máxima basada en el tamaño total de unidades
* Una unidad con tamaño 5 ocupa 5 puntos de capacidad en un slot
* Los slots se llenan completamente antes de pasar al siguiente

2. Mecánicas de Combate Avanzadas
2.1 Attacking Matrix (Am Theory)
Fuente: Estudio académico de AT Barbarossa y Xanto
2.1.1 Concepto Fundamental
Cada línea de batalla forma una matriz de ataque (Am) de dimensiones n × m donde:
* n = número máximo de unidades por slot (ej: 30, 40, 50)
* m = número de slots de la línea (ej: 7 slots)
Cada fila i de la matriz ataca el slot j donde j ≡ i (mod m).
Ejemplo:
35 Steam Rams distribuidos en 7 slots × 5 unidades = matriz 5×7
Fila 1 ataca slot: 1 mod 7 = 1
Fila 2 ataca slot: 2 mod 7 = 2
Fila 3 ataca slot: 3 mod 7 = 3
Fila 4 ataca slot: 4 mod 7 = 4
Fila 5 ataca slot: 5 mod 7 = 5
2.1.2 Implicaciones de la Matriz
Distribución de Ataques:
* NO todos los slots reciben la misma cantidad de ataques
* El slot renumerado como "1" recibe más ataques (más filas lo atacan)
* Slots externos reciben menos ataques
Matriz Completa vs Incompleta:
* Completa: Todos los slots llenos (n unidades cada uno)
* Incompleta: Algunos slots parcialmente llenos
* Slots incompletos alteran el patrón de distribución
2.2 Slot Renumbering
Fuente: Estudio académico - Sección 2.2
2.2.1 Standard Renumbering
Los slots NO se atacan en orden físico [1,2,3,4,5,6,7]. Cada tipo de línea tiene un orden de renumeración específico:
Primera Línea y Segunda Línea:
Orden de daño: [6, 4, 2, 1, 3, 5, 7]
* Slot físico 1 recibe más daño (renumerado como "1")
* Slots centrales (2, 3) reciben segundo nivel de daño
* Slots intermedios (4, 5) reciben tercer nivel
* Slots externos (6, 7) reciben menos daño
Tercera Línea (Artillería):
Orden de daño: [5, 3, 1, 2, 4]
* Máximo 5 slots de artillería
* Patrón diferente a primera/segunda línea
Flancos:
Orden de daño: [6, 4, 2, 1, 3, 5]
* Máximo 6 slots
Bombarderos:
Orden de daño: [1, 2]
* Máximo 2 slots
Anti-Aérea:
Orden de daño: [2, 1]
* Máximo 2 slots
2.2.2 Impacto Estratégico
Posicionamiento Defensivo:
* Colocar unidades más fuertes en slot físico 1 (recibe más daño)
* Slots externos (6, 7) son más seguros para unidades frágiles
Cálculo de Daño:
* El slot renumerado "1" recibe ataques de más filas de la matriz Am
* Necesario considerar renumeración al calcular daño esperado por slot
2.3 Damage Redistribution
Fuente: Estudio académico - Secciones 4, 8, 10
2.3.1 Reserve-Redistribution (RR)
Cuándo: Al inicio de cada ronda
Mecánica:
damage_per_slot = (total_damage / total_units_alive) × units_in_slot
El daño total acumulado se redistribuye entre TODAS las unidades vivas, incluyendo las que están en reserva.
Ejemplo:
Ronda 1: 100 hoplitas con HP 56 c/u
Daño total recibido: 3000
Ronda 2 inicia: RR distribuye 3000 entre 100 = 30 daño por unidad
Todas empiezan ronda 2 con HP 26
2.3.2 Slot-Redistribution (SR)
Cuándo: Después que una línea dispara
Mecánica:
Secuencia:
1. Segunda línea dispara → SR en primera línea
2. Primera línea dispara
El daño se redistribuye dentro de cada slot del objetivo después que el atacante dispara.
Ejemplo:
Segunda línea (arqueros) dispara contra primera línea (hoplitas)
Daño total: 500
→ SR: distribuir 500 entre todos los hoplitas de primera línea
Luego primera línea dispara
2.3.3 Immediate-Redistribution (IR)
Cuándo: Durante el ataque (inmediatamente)
Unidades especiales:
* Portaglobos (umbral ≥30)
* Espolones a Vapor (umbral ≥80)
Mecánica:
Ataque 1 llega → IR divide daño entre todas las unidades del grupo
Ataque 2 llega → IR divide daño entre todas las unidades del grupo
...
Ejemplo con Rocket Ships vs Steam Rams:
2 Rocket Ships (439 daño c/u) atacan 5 Steam Rams (576 HP c/u)
Sin IR:
Rocket 1 → Ram 1 muere, Ram 2 recibe daño
Rocket 2 → Ram 2 muere
Resultado: 2 Rams muertos
Con IR (≥80 Rams juntos):
Rocket 1 (439 daño) → IR divide entre 5 = 87.8 daño c/u
Rocket 2 (439 daño) → IR divide entre 5 = 87.8 daño c/u
Total: 175.6 daño por Ram < 576 HP
Resultado: 0 Rams muertos
2.4 Kill Types
Fuente: Estudio académico - Secciones 5-11
El estudio identifica 6 tipos diferentes de kill según cómo se aplica el daño:
2.4.1 One-Shot-kill (1-kill)
Definición: 1 unidad mata exactamente 1 objetivo
Ejemplo:
1 Ram Ship (75 daño) vs 1 Hoplita (56 HP, 1 armadura)
Daño efectivo: 75 - 1 = 74 > 56
Resultado: 1 Hoplita muerto
2.4.2 Direct-kill (D-kill)
Definición: n unidades atacan secuencialmente hasta matar, sin daño sobrante desperdiciado
Ejemplo:
40 Swordsmen (10 daño c/u) vs Hoplitas (56 HP)
Unidad 1-6 atacan Hoplita 1 → 60 daño → Hoplita muere (4 daño sobrante)
Daño sobrante SE REASIGNA
Resultado: Máxima eficiencia
2.4.3 Pig-kill (P-kill)
Definición: Similar a D-kill pero daño sobrante se reasigna misteriosamente
Comportamiento: No completamente entendido en el estudio
2.4.4 Indirect-kill (I-kill)
Definición: Kills calculados por división entera
Fórmula:
kills = floor(sum(all_attacks) / target_HP)
Ejemplo:
100 Hoplitas (18 daño c/u) vs Hoplitas enemigos (56 HP)
Daño total: 100 × 18 = 1800
Kills: floor(1800 / 56) = 32 Hoplitas muertos
2.4.5 IR-kill
Definición: Kill con Immediate Redistribution
Aplicable: Portaglobos, Espolones a Vapor cuando superan umbral
2.4.6 Magical-kill (M-kill)
Definición: Casos donde se pierde daño inexplicablemente
Nota: El estudio no logra explicar completamente este tipo
2.5 Accuracy (Precisión)
Fuente: Estudio académico - Sección 11.1
⚠️ CORRECCIÓN: La precisión NO es siempre 100%
Ejemplo de unidades.json:
{
"nombre-unidad": "lancero",
"precision": 70
}
Mecánica:
Si unidad tiene precision < 100:
ataques_efectivos = floor(cantidad_unidades × (precision / 100))
Ejemplo: 12 Spearmen (70% precisión)
→ Solo 12 × 0.7 = 8 disparan efectivamente
→ 4 unidades "fallan" su ataque
Impacto en Am:
Matriz 12×7 con precisión 70%
→ Solo 8 filas atacan efectivamente
→ Filtrar filas según precisión antes de distribuir ataques
2.6 Incomplete Slots y Battle Field Composition
Fuente: Estudio académico - Sección 13
2.6.1 Slots Incompletos
Problema: Slots con menos unidades de las esperadas rompen Am Theory
Ejemplo:
Slot esperado: 30 unidades
Slot real: 8 unidades
Daño esperado (Am): 500
Daño real recibido: < 500 (overflow a otros slots)
Consecuencia:
* El daño "sobrante" puede ir a otros slots
* Necesario detectar slots incompletos y ajustar cálculos
2.6.2 Composición Completa del Campo
Principio: La presencia/ausencia de una línea afecta daño en otras líneas
Ejemplo:
"The power of an absent second line"
Con segunda línea presente:
Primera línea recibe daño X
Sin segunda línea:
Primera línea recibe daño Y (Y > X)
Implicación: Necesario analizar composición completa del battlefield antes de calcular daño

5.2.1 Módulo de Unidades (Units)
Entidades:

* TerrestrialUnit: Unidades terrestres
* MaritimeUnit: Unidades marítimas
* UnitType: Enum con todos los tipos de unidades
* UnitStats: Value Object con estadísticas (HP, armadura, daño, tamaño, munición, precision)
Servicios:
* UnitFactory: Crea instancias de unidades con stats específicos

5.2.2 Módulo de Campo de Batalla (Battlefield)
Entidades:
* Battlefield: Representa el campo de batalla completo
* BattleLine: Representa una línea de batalla (primera línea, flancos, etc.)
* BattleSlot: Representa un slot dentro de una línea
* BattlefieldConfiguration: Configuración de slots según nivel
* AttackingMatrix: Matriz n×m de unidades atacantes
* SlotRenumbering: Orden de renumeración por tipo de línea
Value Objects:
* BattleType: Enum (Terrestrial, Maritime)
* LineType: Enum (FirstLine, Ranged, Flanks, Artillery, Bombers, AntiAir)
* SlotCapacity: Capacidad de un slot (número de huecos, tamaño por hueco)
Servicios:
* BattlefieldFactory: Crea campos de batalla según nivel de ciudad/puerto
* UnitDistributionService: Distribuye unidades en slots según prioridades
* SlotFillingAlgorithm: Implementa el algoritmo de llenado de slots
* AttackingMatrixService: Construye y gestiona matriz de ataque (Am)
* SlotRenumberingService: Aplica renumeración según tipo de línea
* BattlefieldAnalyzer: Analiza composición completa del campo
5.2.3 Módulo de Combate (Combat) - ACTUALIZADO
Entidades:
* Battle: Representa una batalla completa
* BattleRound: Representa una ronda de combate
* AttackAction: Representa un ataque individual
* DamageResult: Resultado de un ataque
* KillType: Enum con tipos de kill (1-kill, D-kill, P-kill, I-kill, IR-kill, M-kill)
Servicios:
* CombatEngine: Motor principal de combate
* DamageCalculator: Calcula daño efectivo con precisión
* TargetSelector: Selecciona objetivos según prioridades y Am

Agregados:

5.2.4 Módulo de Reportes (Reporting)

Ikariam es un juego de estrategia con batallas entre unidades que tienen estadísticas (HP, armadura, daño, tamaño, munición, precisión). Las unidades pueden tener mejoras INDIVIDUALES (mejora0, mejora1, mejora2, mejora3) y bonificaciones de Hefesto GLOBALES (niveles 0-5).
REQUISITO CRÍTICO 1: MEJORAS INDIVIDUALES
Las mejoras se aplican INDIVIDUALMENTE a cada unidad, NO globalmente por tipo.
Ejemplo:
Un jugador puede tener:
* 100 espadachines sin mejora (mejora 0)
* 50 espadachines con mejora 2
* 30 espadachines con mejora 3
Estos son 3 GRUPOS DIFERENTES que se gestionan independientemente.
REQUISITO CRÍTICO 2: HEFESTO GLOBAL
Hefesto se aplica GLOBALMENTE a todas las unidades del bando.
Tabla completa:
* Nivel 0: +0 armadura, +0% daño
* Nivel 1: +0 armadura, +7.5% daño
* Nivel 2: +10 armadura, +7.5% daño
* Nivel 3: +10 armadura, +10% daño
* Nivel 4: +20 armadura, +12.5% daño
* Nivel 5: +20 armadura, +15% daño
REQUISITO CRÍTICO 3: PRECISIÓN VARIABLE
NO todas las unidades tienen 100% precisión. Algunas unidades (ej: Lancero) tienen precisión 70%.
REQUISITOS DE IMPLEMENTACIÓN:
1. Crear una clase abstracta Unit con las siguientes propiedades:
   * id: string
   * name: string
   * type: UnitType (enum)
   * battleType: BattleType (enum: Terrestrial, Maritime)
   * lineType: LineType (enum: FirstLine, Ranged, Flanks, Artillery, Bombers, AntiAir)
   * stats: UnitStats (Value Object)
   * currentHP: number
   * currentAmmunition: number | null
   * upgradeLevel: number (0-3) // Mejora INDIVIDUAL de esta unidad específica
   * groupId: string // Identificador único: ${type}_upgrade${level}
2. Crear Value Object UnitStats con propiedades inmutables:
   * baseHP: number
   * baseArmor: number
   * baseDamage: number
   * accuracy: number // Precisión (0-100)
   * size: number
   * ammunition: number | null
   * upgradeDamage: [number, number, number, number] // mejora0, mejora1, mejora2, mejora3
   * upgradeArmor: [number, number, number, number]
3. Implementar método Unit.getEffectiveStats(hephaestusLevel: number):
getEffectiveStats(hephaestusLevel: number): EffectiveStats {
const hephaestus = HephaestusService.getBonuses(hephaestusLevel);
// Armadura: base + mejora individual + hefesto global
const armor = this.stats.baseArmor
+ this.stats.upgradeArmor[this.upgradeLevel]
+ hephaestus.armor;
// Daño: (base + mejora individual) × (1 + hefesto%)
const damage = (this.stats.baseDamage
+ this.stats.upgradeDamage[this.upgradeLevel])
× (1 + hephaestus.damagePercent);
return {
hp: this.stats.baseHP, // HP no se modifica
armor: armor,
damage: damage,
accuracy: this.stats.accuracy,
size: this.stats.size,
ammunition: this.stats.ammunition
};
}
4. Implementar HephaestusService con tabla completa:
class HephaestusService {
private static readonly BONUSES = {
0: { armor: 0, damagePercent: 0.00 },
1: { armor: 0, damagePercent: 0.075 },
2: { armor: 10, damagePercent: 0.075 },
3: { armor: 10, damagePercent: 0.10 },
4: { armor: 20, damagePercent: 0.125 },
5: { armor: 20, damagePercent: 0.15 }
};
static getBonuses(level: number): { armor: number; damagePercent: number } {
if (level < 0 || level > 5) {
throw new Error(Invalid Hephaestus level: ${level}. Must be 0-5.);
}
return this.BONUSES[level];
}
}

class UnitGroup {

class AttackingMatrix {
private matrix: Unit[][]; // matriz n×m
private n: number; // filas (unidades por slot)
private m: number; // columnas (número de slots)
constructor(battleLine: BattleLine) {
this.m = battleLine.slots.length;
this.n = battleLine.getMaxUnitsPerSlot();
this.buildMatrix(battleLine);
}
private buildMatrix(battleLine: BattleLine): void {
this.matrix = [];
for (let row = 0; row < this.n; row++) {
 this.matrix[row] = [];
 
 for (let col = 0; col < this.m; col++) {
   const slot = battleLine.slots[col];
   const units = slot.getAliveUnits();
   
   // Asignar unidad en posición (row, col) si existe
   if (row < units.length) {
     this.matrix[row][col] = units[row];
   } else {
     this.matrix[row][col] = null;  // Slot incompleto
   }
 }
}

}
getTargetSlotForRow(row: number): number {
// Fila i ataca slot j donde j ≡ i (mod m)
return (row + 1) % this.m || this.m; // 1-indexed
}
getAttackersForSlot(targetSlotIndex: number, renumbering: number[]): Unit[] {
const attackers: Unit[] = [];
// Encontrar qué filas atacan este slot según renumeración
const renumberedIndex = renumbering.indexOf(targetSlotIndex + 1);  // 1-indexed

for (let row = 0; row < this.n; row++) {
 const targetSlot = this.getTargetSlotForRow(row);
 
 if (targetSlot === renumberedIndex + 1) {
   for (let col = 0; col < this.m; col++) {
     if (this.matrix[row][col] !== null) {
       attackers.push(this.matrix[row][col]!);
     }
   }
 }
}

return attackers;

}
isComplete(): boolean {
// Verificar si todos los slots están llenos
for (let row = 0; row < this.n; row++) {
for (let col = 0; col < this.m; col++) {
if (this.matrix[row][col] === null) return false;
}
}
return true;
}
getDimensions(): { rows: number; cols: number } {
return { rows: this.n, cols: this.m };
}
}

Prompt Fase 4: Damage Redistribution (NUEVO - CRÍTICO)
Eres un ingeniero experto. Implementa los 3 tipos de Damage Redistribution basándote en el estudio académico de AT Barbarossa y Xanto.
CONTEXTO:
El sistema de combate de Ikariam aplica 3 tipos diferentes de redistribución de daño en momentos específicos:
                                    1. Reserve-Redistribution (RR): Al inicio de cada ronda
                                    2. Slot-Redistribution (SR): Después que una línea dispara

REQUISITO CRÍTICO 1: RESERVE-REDISTRIBUTION (RR)
Cuándo: Al inicio de cada ronda, antes de cualquier ataque.
Mecánica:
damage_per_slot = (total_damage / total_units_alive) × units_in_slot
El daño total acumulado se redistribuye entre TODAS las unidades vivas (incluyendo reserva).
Implementación:
class ReserveRedistributionService {
applyRR(battlefield: Battlefield, side: 'attacker' | 'defender'): void {
const lines = battlefield.getLines(side);
let totalDamageAccumulated = 0;
let totalUnitsAlive = 0;
// Paso 1: Calcular daño total y unidades totales
for (const line of lines.values()) {
 for (const slot of line.slots) {
   for (const unit of slot.getAliveUnits()) {
     totalDamageAccumulated += (unit.stats.baseHP - unit.currentHP);
     totalUnitsAlive++;
   }
 }
}

if (totalUnitsAlive === 0) return;

// Paso 2: Redistribuir daño equitativamente
const damagePerUnit = totalDamageAccumulated / totalUnitsAlive;

for (const line of lines.values()) {
 for (const slot of line.slots) {
   for (const unit of slot.getAliveUnits()) {
     // Resetear HP y aplicar daño redistribuido
     unit.currentHP = unit.stats.baseHP - damagePerUnit;
   }
 }
}

}
}

}

REQUISITO CRÍTICO 3: IMMEDIATE-REDISTRIBUTION (IR)
Cuándo: Durante el ataque (inmediatamente al recibir daño).
Unidades especiales:

                                    * Espolones a Vapor: Umbral ≥80 unidades

class ImmediateRedistributionService {
private static readonly IR_UNITS = {
'barco-portaglobos': { threshold: 30 },
'barco-espolon-vapor': { threshold: 80 }
};
shouldApplyIR(units: Unit[]): boolean {
if (units.length === 0) return false;
// Verificar si todas son del mismo tipo
const firstType = units[0].type;
if (!units.every(u => u.type === firstType)) return false;

// Verificar si es tipo especial
const config = this.IR_UNITS[firstType];
if (!config) return false;

// Verificar umbral
return units.length >= config.threshold;

}
applyIR(slot: BattleSlot, incomingDamage: number): Unit[] {
const aliveUnits = slot.getAliveUnits();
if (!this.shouldApplyIR(aliveUnits)) {
 // Sin IR: aplicar daño normal a primera unidad
 return this.applyNormalDamage(slot, incomingDamage);
}

// Con IR: dividir daño entre todas
const damagePerUnit = incomingDamage / aliveUnits.length;
const casualties: Unit[] = [];

for (const unit of aliveUnits) {
 unit.currentHP -= damagePerUnit;
 
 if (unit.currentHP <= 0) {
   casualties.push(unit);
   slot.removeUnit(unit);
 }
}

return casualties;

}
private applyNormalDamage(slot: BattleSlot, damage: number): Unit[] {
const target = slot.getFirstAliveUnit();
if (!target) return [];
target.currentHP -= damage;

if (target.currentHP <= 0) {
 slot.removeUnit(target);
 return [target];
}

return [];

}
}

Apéndices
Apéndice A: Glosario de Términos (ACTUALIZADO)
                                                         * HP (Hit Points): Puntos de vida de una unidad
                                                         * Armadura: Reducción de daño recibido
                                                         * Daño: Daño base infligido por una unidad
                                                         * Precisión (Accuracy): Porcentaje de ataques efectivos (0-100%)
                                                         * Tamaño: Espacio que ocupa una unidad en un slot
                                                         * Munición: Número de ataques que puede realizar una unidad antes de retirarse a la reserva
                                                         * Reserva: Estado de unidades sin munición que ya no participan en el combate
                                                         * Slot: Espacio en una línea de batalla que puede contener unidades
                                                         * Línea de Batalla: Agrupación de unidades por función (primera línea, flancos, etc.)
                                                         * Orden de Ataque: Secuencia en que las líneas atacan (1-6)
                                                         * Prioridad de Ataque: Objetivos preferidos de cada línea
                                                         * Mejora Individual: Nivel de mejora (0-3) de cada unidad específica
                                                         * Hefesto Global: Bonificación (niveles 0-5) aplicada a todas las unidades del bando
                                                         * Attacking Matrix (Am): Matriz n×m de unidades atacantes que determina distribución de ataques
                                                         * Slot Renumbering: Orden específico en que los slots reciben ataques según tipo de línea
                                                         * Reserve-Redistribution (RR): Redistribución de daño entre todas las unidades al inicio de ronda
                                                         * Slot-Redistribution (SR): Redistribución de daño dentro de cada slot después que línea dispara
                                                         * Immediate-Redistribution (IR): Redistribución de daño durante ataque (Portaglobos/Espolones)
                                                         * Kill Type: Tipo de eliminación (1-kill, D-kill, P-kill, I-kill, IR-kill, M-kill)
Apéndice B: Fórmulas Matemáticas (ACTUALIZADAS)
Daño Efectivo:
Daño_Efectivo = MAX(0, Daño_Atacante - Armadura_Defensor)
Armadura con Mejoras Individuales y Hefesto Global:
Armadura_Final = Armadura_Base + Armadura_Mejora_Individual[nivel] + Armadura_Hefesto_Global[nivel]
Daño con Mejoras Individuales y Hefesto Global:
Daño_Final = (Daño_Base + Daño_Mejora_Individual[nivel]) × (1 + Bonus_Hefesto_Global[nivel])
Attacking Matrix - Distribución de Ataques:
Fila i ataca Slot j donde: j ≡ i (mod m)
Reserve-Redistribution:
damage_per_unit = total_damage_accumulated / total_units_alive
HP_unit = HP_base - damage_per_unit
Slot-Redistribution:
damage_per_unit_in_slot = total_damage_in_slot / units_in_slot
HP_unit = HP_base - damage_per_unit_in_slot
Immediate-Redistribution:
Si units_in_slot >= threshold:
damage_per_unit = incoming_damage / units_in_slot
Sino:
damage_to_first_unit = incoming_damage
Indirect Kill (I-kill):
kills = floor(sum(all_attacks) / target_HP)
Ataques Efectivos con Precisión:
effective_attacks = floor(total_units × (accuracy / 100))
